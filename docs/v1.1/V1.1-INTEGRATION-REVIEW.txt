二、前端结构与功能
Vue3+Vue Router+Axios+Element Plus，Vite7.3.8；Node24.16.0/npm11.13.0在本机可安装构建。
main.js：Hash路由，/login、/student、/admin、/repairer；真实模式按/api/auth/me身份守卫，不允许任意切换角色页面。
LoginView.vue：真实登录、保存accessToken、查询me、清空密码、处理登录错误。
session.js/App.vue：sessionStorage保存Token，显示用户名，登出清理Token及跳转登录。
RepairWorkspace.vue：学生提交、工单列表、状态筛选、管理员审核/驳回/派单、维修开始/提交结果、学生验收/返工；刷新、操作弹窗、基础提示和统计。
orders.js：Axios统一/api和Bearer请求头，真实/模拟模式；真实列表与维修人员分页拉取；操作前查allowedActions。
八种工单状态均与后端一致；rework前端操作映射为accept(false)，不误调/rework旧接口。

三、契约核对
已匹配：POST/auth/login、GET/auth/me、GET/POST/repair-orders、approve/reject/assign/start/finish/accept、GET/{id}/workflow、GET/users/repairers。
登录返回accessToken、角色大写转小写路由、Bearer、工单列表数组、维修人员items/total、allowedActions格式均匹配。
live模式创建仅发送title/location/description，开始不发送伪造ID，finish仅description，accept仅approved。管理员派单repairerId是目标人员，符合契约。
401有全局清除登录及跳转；409关闭弹窗并刷新列表；其他错误有通用message提示。

四、发现的问题/未接入功能（本轮未改页面）
P0 配置：VITE_DATA_MODE只有严格等于live才真实请求。默认没有.env.local时会落入localStorage模拟模式，能切角色，不代表真实权限或后端验证。本轮已在被忽略的.env.local启用live。
P1 维修结果：RepairWorkspace.vue:310显示row.repairResult，但该字段只在orders.js:93模拟流程写入。真实后端列表不返回此字段，维修结果在GET/{id}/records。前端未调用records，真实维修结果/多次返工记录尚未展示。
P1 待办口径：RepairWorkspace.vue:80按角色+状态推算pending，未调用GET/api/workflow/tasks。它不是引擎真实待办，在流程挂起、任务归属异常等情况会与后端不同。
P1 操作按钮：RepairWorkspace.vue:334按静态状态表显示；只有点击时:150才查allowedActions。安全上后端仍拦截，但可能出现按钮可见而点击被拒绝，建议确认后按后端动作统一可用性。
P1 查询未展示：GET/{id}详情、GET/{id}/records、当前节点/结束标记/LEGACY模式尚无独立展示；当前展开区域只使用列表description和模拟repairResult。
P2 分页：orders.js:49、109循环取完全部页再本地筛选/渲染，无页面分页控件或总量展示；格式匹配，但大数据量下耗时和内存增加。建议先功能闭环，再决定是否接服务端筛选分页。
P2 字段命名：模拟数据studentId/repairerId，真实数据student_id/repairer_id；live模式绕过本地ID过滤，当前列表核心字段可正常用，但后续身份/详情展示需明确转换。
P2 输入范围：前端标题80、地点100、描述/维修说明500；后端标题100、地点200，描述未设同样500限制。前端更严格，不会导致现有提交失败，但需双方确认统一范围。
P2 提示：403/404/503主要显示通用后端message，未形成各状态的专门交互；状态筛选和待办统计仅在当前拉取结果上计算。
P2 默认模拟模式、README演示说明容易使验收误判；后续可强化真实/演示模式辨识，但本轮不改视觉设计。
没有发现live模式硬编码可登录的账号/密码；1/2等ID属于模拟状态默认值，真实请求封装已剔除操作人字段。不要将模拟角色切换当成JWT权限测试。
