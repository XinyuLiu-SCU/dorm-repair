# 06 智能派单算法设计

定位：可解释约束筛选与排序，不引入机器学习平台或自动替管理员决定。无足够数据时返回原因及手工调度入口，不编造技能/工时/位置。

## 输入与硬约束

输入工单版本、类别/设施位置、学生期望窗口、预计工时、入室方式；候选启用维修人员、有效技能、实际班次、已批准请假、确认预约、当前负载及配置版本。V1无结构化类别的单不启用自动推荐。

硬约束：账号和工作权限有效；技能覆盖选定项目；工作+必要路程位于班次内；不与请假/有效预约重叠；需要入室时具备到场安排或有效授权。学生“期望”能否作为软约束需明确选择；默认不能未经协商就订到窗口外。

缺少技能登记不默认具备全部技能；缺少位置不默认距离为零；工时无配置返回低置信度并要求人工确认。管理员可以覆盖软排序并写原因，不能静默越过硬约束。

## 可行时间与排序

将班次减去请假、预约，得到空闲区间；与学生窗口求交，验证预计工时及路程缓冲能否容纳。半开区间[start,end)允许前一预约结束时后一预约开始，但实际路程缓冲仍必须计入。

对合格候选计算：

`score = w_load * loadScore + w_distance * distanceScore + w_time * timeScore`

各分数归一化0..1，权重非负且和为1。技能是硬门槛，不用高评分抵消无技能。负载按有效工作分钟而非简单工单数量；距离先用同楼/楼间配置和楼层差，缺坐标时给缺失标记，不依赖外部地图。

建议试验权重0.4/0.3/0.3、Top3或Top5，但都只是候选，不是已确认业务规则。配置版本和原始分量写入推荐快照，以便解释和重放；相同分数按可开始时间、当日负载、人员ID稳定排序，不随机漂移。

不在第一版引入基于学生主观差评的自动惩罚排序，避免样本不足和偏差。

## 推荐与派单分离

推荐不占用资源。建议课程版只在预约确认时建立排他预订，派单/接单不等于已订到具体时间；若后来冲突，返回409并协商改期。另一候选是短期HELD预订，但保留时长和超时释放政策需先确认。

管理员提交选择时携带orderVersion、recommendationId、appointmentVersion。服务重新锁工单及目标人员并检查硬约束，过期推荐不直接执行。多人同时确认同一人员同一时段只能一方成功。

无需扩展btree_gist即可先用人员行锁+重叠查询保证排他；所有相关写路径必须遵守同一协议。若未来采用GiST排他约束，需要额外extension审批和独立演练。

## 复杂度与失败情形

R个人、每人K个区间，排序合并约O(R*K log K)，通过窗口批量查询避免每人逐条查库。分页/日期上限配置化，建议只查未来一周并限制候选数；具体上限由课程演示规模确认。

无候选：返回NO_SKILL/NO_SHIFT/LEAVE/BOOKED/ACCESS_MISSING/DATA_INCOMPLETE等原因分布，前端可改期或交管理员；不能直接派给一个不满足条件的人。

## 验收用例

- 有技能但请假：排除；同楼但已订：排除；跨楼可达：可排序。
- 边界时间、跨日/时区、零空闲、缺位置、缺工时均有明确结果。
- 两个管理员同时选择同一时段：一方成功，另一方409且无重复预订。
- 推荐后新增请假/禁用账号/变更技能：提交时拒绝旧建议。
- 输出每个分数分量、约束原因和配置版本；用小样本穷举验证可行性，不只验证排序代码自身。

## 候选评分公式与实现伪代码

建议使用以下可复现初版，业务确认后才固定参数：

- loadScore = 1 - min(1, 已预约分钟/可用班次分钟)，分母<=0则不可行，不以0负载掩盖没班次。
- distanceScore = 1 - min(1, 预计路程分钟/Dmax)，Dmax来自学校楼间配置；缺位置的候选单列低置信度，不按0距离并入正常排名。
- timeScore = 1 - min(1, (最早可开始时间-期望窗口起点)/窗口长度)，先保证完整维修区间在可行窗口中；零长度窗口直接校验失败。

路程从前一预约位置到本单、并考虑本单至后一预约，不能只从维修人员常驻楼计算。楼间信息缺失或工时无配置时只返回待人工确认候选，不确认排他预约。

```text
校验工单/类别/时间窗
批量载入启用人员、技能、班次、请假、预约与位置
for 每个候选人员:
    不满足账号/技能 -> 记录淘汰原因
    intervals = 班次 - 请假 - 预约及路程缓冲
    feasible = intervals 与学生窗口相交且容纳预计工时
    无可行区间 -> 记录原因
    否则计算分量及置信度，追加候选
按置信度组、加权分数降序及稳定次序返回TopK和解释
管理员选择 -> 在写事务内重载并验证，不直接相信推荐快照
```
