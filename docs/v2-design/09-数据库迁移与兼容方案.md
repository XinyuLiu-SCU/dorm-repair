# 09 数据库迁移与兼容方案（R2）

仅设计，无V2 DDL执行、无正式连接写入、无流程部署或开关变更。V1.1 stable标签及旧标签保留。正式库dorm_repair_db仍只有原三张业务表，隔离库已有引擎/关联/legacy，演练库有版本账，三者不可互换配置。

## 1. 分期扩展与前置

|交付|必要扩展|禁止误用|
|---|---|---|
|V2.0|用户/RBAC、分类/位置/资产、地址与资料快照、图片绑定、期望/工时历史|不把原location猜成结构化房间，不重置密码|
|V2.1|cycle/epoch、预约参与决定/排他预订、SLA/deadline、process_link、多任务DTO；提前最小技能班次通行/材料预留实发退交账|完整库存功能V2.2但真实并行必须有最小真实资源路径；不能模拟READY或无视已发材料|
|V2.2|完整技能/排班/推荐、库存入出库/成本核对/预警|不能覆盖已发单位成本，推荐不直接占用预约|
|V2.3|公共关联epoch/争议、inspection batch/MI/周期唯一|不能多工单共用root pi，timer新定义未批准不得部署|
|V2.4|评价/投诉/回访、通知/统计/知识库|基础Outbox/提醒与审计提前V2.1，不能等最后才补可靠性|
|V3.0|只做验证过的索引/部署/契约优化|不是删除旧字段/数据的自动授权|

## 2. 兼容迁移步骤（未来需逐次批准）

1. 在隔离副本核对真实schema/引擎版本、全部业务行摘要和密码哈希摘要，确认可恢复备份；工单1/2/3和原记录逐项保护。
2. 正式尚未具备V1结构，先单独批准并演练V1关联与引擎迁移；V2不能绕过此门禁。
3. Expand追加可空字段和新表，保留原ID/字段/粗状态；generation按实际V1和LEGACY登记回填，缺实例不自动视LEGACY。
4. 旧地址仅LEGACY_TEXT，新资料版本/联系人不补造；历史revision/cycle不可凭空编造为已验证事实，可使用明确LEGACY_IMPORT行并标缺失值，或只在新V2单强制新约束。
5. CHECK/FK可NOT VALID后VALIDATE，唯一/NOT NULL单独验证与建立；CONCURRENTLY索引不在普通事务脚本里。组合FK校验房间/楼栋、资料/轮次同单。
6. 角色种子映射原三角色，enabled=true/auth_version=0，不改哈希。旧无authVersion JWT只在批准的有限窗口且DB版本0/未停用时兼容，变权立即失效；窗口值仍待确认。
7. 保持V1原接口适配；V2新DTO字符串ID、多任务数组、新粗状态CANCELLED。旧写入口拒绝V2单，旧前端不能跳过预约/材料节点。
8. 将新流程只部署到未来隔离V2配置，绑定实际definitionId及call目标版本，不使用latest。通过同库V1在途/终态/LEGACY+V2多分支矩阵后申请正式发布。
9. 在隔离环境明确开启异步executor验证timer持久化、重启/多实例/失败重试；当前正式与8080开关/密钥保持。部署inspection timer start前设独立发布门禁和计划启用范围，避免部署即全校跑批。

## 3. 流程及变量版本

V1 dormRepair不改；V2 root及材料/巡检/投诉/回访definition分别版本化。process_link保存实际definitionId、parent、cycle/epoch；callActivity固定版本/部署组合，不能父流程历史实例下一次返工突然调用不兼容新材料流程。业务BPMN版本与引擎7.2.0/schema7.2.0.2是不同维度。

并行路由输出用分支execution local或专门prepare业务行，禁止两个分支同时写root同名outcome。候选XML的服务delegate、变量in/out、事件correlation需开发阶段实现；本轮XML未绑定真实业务Bean，也未部署。增加活动不能对旧运行实例直接changeActivityState。

公共关联/解绑递增linkEpoch，主结果版本纳入消息唯一键；旧关联迟到消息标SKIPPED。巡检计时启动和多实例目标快照的唯一周期不能因重新部署被绕开。

## 4. 资源、文件与回退

资料/附件历史和位置快照永久不随地址簿或设施移动改写；后续留存删除需单独批准并满足隐私规则。旧timestamp无时区先核实来源，新字段timestamptz，不能盲目批量转Asia/Shanghai。

回退优先停新V2创建而保留适配器收尾在途；已发材料不能回滚旧程序删除账，已发通知也不能假装从未发生。转派/中断失败整体回滚本命令；历史已提交实发留存，以新退料/交接流水前滚处理。新实例存在后不可直接回滚到完全不认识并行/epoch/新stage的旧应用。

正式引擎升级、DDL、恢复备份、数据清理和密钥变更均需另行授权。本轮不提供可直接执行的V2正式迁移脚本，不开启正式写入。

## 5. 验证门禁

与10验收ID逐项对照：历史摘要、旧JWT/权限、V1/API回归、并行两顺序与无配件、scope中断/资源清理、定时边界实际触发、callback竞态/死锁、成本原价退料、位置组合FK、资料/预约/返工版本、公共多实例和巡检MI。任何一项未实测在报告中写“未验证”，不能用XML静态校验冒充运行通过。
