# 01 需求规格说明（R2）

修订日期：2026-11-25。状态：第二轮设计，未实现V2业务、未部署候选流程、未迁移数据库。01–10、变更日志与models/构成同一评审基线。需求优先级统一为 MUST / SHOULD / LATER；交付版本仅使用V2.0、V2.1、V2.2、V2.3、V2.4、V3.0，不再用P0/P1/P2兼指优先级与阶段。

## 1. 现有基线与保留原则

V1.1已有Spring Boot 3.5.16、Java21、PostgreSQL17.6、JdbcTemplate三层、Security/JWT、Flowable7.2.0、Vue3/Element Plus；报修、审核/驳回、手工派单、维修/多次返工/验收、真实记录和待办、LEGACY识别、行锁与事务已验收。正式库仅三张业务表；隔离库已有V1关联与引擎结构，不能混淆。

保留模块化单体、动态RBAC方向、地址快照、私有附件、同DataSource/事务管理器、Outbox、可解释派单、历史数据保护。dormRepairV2使用独立key，V1在途继续原定义，不自动迁移或重启历史单。

## 2. 已采纳的第一版规则（本表为全套文档权威规则索引）

|规则ID|已确认规则|落地/边界|

“每组6张”、5MB字节换算、自然日计时是本轮为消除契约歧义的技术口径；若校方有不同口径需评审明确调整，不隐藏为代码默认值。

## 4. 权限与隐私

学生只操作本人报修/资料/授权/评价/验收；维修者只操作当前分配且有功能权限的任务；管理员按review/dispatch/asset/stock/complaint/audit权限分离。自定义多角色是权限并集与数据范围相交，不凭名称获得全权。任务候选不等于可绕过权限；仓库管理员不能因为有材料任务而看到宿舍电话。

地址簿不是住宿登记；room_resident由授权人员确认。公共投影不包含原单ID集合、房号、联系人或原照片EXIF；投诉不默认对被投诉人公开。原维修者转派后不能继续操作，仅允许受控查看其本人记录所需最小字段，具体留存期待校方确认。

## 5. 非功能与待决事项

所有列表有界分页最大100，关联批量查询；订单/引擎/记录同成同败；并行是工作等待并行，数据库命令可以按工单锁串行提交。定时与跨流程事件至少一次，去重不靠前端。附件存私有目录，不给JWT URL。设计性能用真实样本测P95，不承诺未经测量毫秒数。

仍待业务确认：校方实际入室规则/代理资格、异常返工提醒阈值、预约协商提醒间隔、各类SLA暂停口径、评价是否允许编辑及投诉留存、库存财务计价批准、公共争议处理时限、巡检周期漏跑补发上限、课程MVP人力。已确定的图片/分类/7天/15天规则不再列为未决。
