# 04 数据库数据字典

本文件是V2逻辑设计，不是已实现字段或可执行SQL。以现有sys_user、repair_order、repair_record为增量基础，数据库变更逐阶段单独评审。09定义迁移与历史保护规则。

## 通用约定

新增主键bigint identity；API V2把ID编码为十进制字符串，避免JavaScript精度损失。金额numeric(12,2)、数量numeric(12,3)，禁止浮点金额。新增时间timestamptz，区间为[start,end)，check start < end；已有timestamp未经时区核验不自动转换。可变聚合有version integer not null default 0。created_at默认当前时间；updated_at由应用统一设置。状态使用varchar加check，枚举更改需版本迁移。下表所有必填业务关联均使用外键，历史引用on delete restrict；停用替代删除。

密码哈希沿用BCrypt，不在任何查询DTO返回。电话号码属于私密信息。常用查询索引末尾追加id保持稳定排序。除明确可空项外，标识、状态、业务必需字段均not null；可选说明/尚未发生时间可以为空。长度与数量上限在实施前按01待确认规则冻结。

## 事务和一致性落点

- 工单命令：锁order，检查版本/身份/合法节点，写业务与Flowable、记录、审计、Outbox；任何失败整体回滚。同一DataSource/事务管理器沿用V1验证。
- 预约：先order后按ID排序锁涉及的repairer用户行，重验排班/请假/预约区间；释放旧预订、确认新预订、更新Flowable同事务。请假操作锁人员行后发现已有预约返回冲突，不逆向锁工单。
- 库存：order→人员（若涉及）→按item_id升序锁stock_balance；申请批准增加reserved，发料同时减少on_hand/reserved并写唯一流水和usage；不足返回409，不出现负库存。通知不在事务内调用外网。
- 默认地址：锁sys_user行，取消旧默认再设新默认，部分唯一索引兜底。
- 定时巡检：唯一(plan_id,scheduled_at)兜底，SKIP LOCKED领取到期计划；异常转单有唯一finding关联，失败不留下半个流程。
- Outbox至少一次投递；消费事件键唯一去重，失败不能静默标成功。SQL分页和批量关联取数，避免N+1。

所有JSON仅用于推荐快照/脱敏事件，不把可关联核心业务藏在无约束JSON。正式DDL、索引执行计划和数据回填脚本在对应开发阶段再产出、测试、授权。

权限变更事务统一锁定授权管理哨兵行（或明确的同一管理聚合锁），按用户ID顺序更新受影响用户auth_version，防止两个管理员并发互相停用后无可用管理者。角色权限更新、最后管理者检查及会话失效必须原子完成；哨兵存于单行system_guard表（guard_key主键，version），不引入外部锁服务。
