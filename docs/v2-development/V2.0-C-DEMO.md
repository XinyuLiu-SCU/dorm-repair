# V2.0-C 一键幂等合成演示数据

## 前提与命令

只允许本机dorm_repair_v2_dev，必须先通过V6安全迁移。脚本不接收任意数据库地址，不创建账号、不读取/重置用户密码，不复制任何正式资料。首个管理员仍单独使用B阶段initialize-v2-admin.ps1由操作者安全设置密码；该工具与演示工具互相独立。

在仓库根目录PowerShell执行：
```powershell
$env:V2_DB_USER = '<本地数据库用户>'
# 需要密码时由本机安全环境提供V2_DB_PASSWORD，勿提交凭据。
.\scripts\initialize-v2-demo.ps1
```

脚本编译并构造运行classpath，调用DemoTool；固定连接127.0.0.1:5432/dorm_repair_v2_dev，Java再次验证元数据与catalog、V6成功记录。所有写入与audit在一个事务，锁rbac-admin→foundation-catalog。失败整批回滚，无自动清库/覆盖/修复。

## 合成数据规模

2校区、4楼栋、12楼层、48房间、8分类子级、32故障项目、12设施类型、60设施（40公共、20私人）。编码均SYNTHETIC_，名称为虚构内容，房间不关联学生或联系方式。房间编号由所属楼层和SYNTHETIC_编号共同定位。

campus/building/category/item/type通过稳定code定位；floor通过building_id+floor_no；room通过floor_id+room_no；facility通过asset_no。存在则保留，新增才创建。已有名称、启停、排序、工时、资产状态及二维码均不覆盖；结构关系冲突明确拒绝并回滚，不擅自搬迁位置或改类型。

类型新建时写默认关联，已有类型的关联不重写，包括操作者手动清空的关联；这是保护人工修改的明确规则。若已有类型缺少某个默认关联，工具不会猜测并补回，应由管理员显式编辑。重复执行会追加一次脱敏初始化审计，但不重复创建业务对象。报告仅打印created/retained计数，不打印定位码或凭据。
