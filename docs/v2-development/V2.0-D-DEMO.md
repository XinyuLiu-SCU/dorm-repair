# D阶段演示与测试

先安全完成V7–V10迁移，再按B初始化说明由操作者提供合成管理员凭据；不设置默认密码。复用C的SYNTHETIC校园/房间/设施数据，initialize-v2-demo.ps1不创建住户或地址。

本轮不把测试用户写入开发库。真实HTTP测试在独立dorm_repair_v2_test_preparation使用UUID密码及合成姓名/00000000000联系方式，演示入住先由显式residency:manage管理员通过API确认，再由相应学生查看私人设施。选择实际PRIVATE房间及设施，不凭房号/二维码授权。

建议手工联调顺序：创建合成学生（赋address:own/residency:own/draft:own及C只读权限）→学生创建地址→管理员确认有效期入住→学生查看设施及预填→保存不完整/完整资料→修改源地址验证旧版本快照→追加新版本/撤回无人值守意愿→放弃资料。全程不调用正式工单创建，不显示提交成功。

完整自动化命令：先设置本地V2_DB_USER及安全数据库凭据，scripts/prepare-v2.ps1 -IncludeRegression准备允许列表中的测试库，再运行scripts/test-v2.ps1。脚本默认仅V2测试库，不能指定正式目标；测试类对重置目标再次核验元数据。原V1回归只在专用v2_test_v1/rehearsal运行。

新V7对非空库需要可信逐用户映射，不能把测试fixture映射直接用于实际账号。若开发库出现真实数据冲突，必须停止该库迁移并人工核验，不能复制正式库密码或住宿资料来填充。
